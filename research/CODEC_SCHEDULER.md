# EO-IC100 0.23 codec scheduler map

Offline analysis only. No USB, firmware patch, or tuner changes. Source image
is official 0.23 `stock_b.bin` (SHA-256
`2f418d3a324ec4217c32c4bf98d43c3cd07d59d81f82974f29320d399fa769f3`); the
initialized-RAM xref cache is `571d2d9a2d78cca002c970c8f0c73d15785ee5a2309eafe9d3ff807fbf398567`.
The deterministic compact index is generated by
`python3 tools/research/codec_scheduler_audit.py` and stored in ignored
`research/cache/custom-vendor/codec-scheduler-analysis.json`.

## INFERRED

- The `0x20aa20` loop is the best codec-control execution-context candidate: it is software event/configuration work, not the known frame callback, and stock EQ reconfiguration reaches the setter through its command handler.
- The ring stores a uint32 command word: command ID is bits 0–7, observed arguments are bits 8–23; the reviewed consumer does not use bits 24–31. A new command could carry a token while a single-slot mailbox holds the validated EQ structure. The raw push is a bounded single try; an EP0 producer must handle full/contended status without retrying.
- The stock producer's notification path is `0x204758(3)`, which ORs bit 3 in `0x20019a0c` with a short PRIMASK-preserving update. The command handler clears that bit at entry (`0x20d1d0`), drains the ring, and the app loop then calls `0x209a8c`. Its event-service body reads the shared word; this is a software flag path, not evidence of an RTOS event-group wake call.
- The Thumb table at `0x20d20a` dispatches IDs `0x00`–`0x14`; ID `0x13` is the only in-table ID routed to the generic unknown-command logger at `0x20d418`. It is the least disruptive candidate: special-case `0x13` at that fallback and leave the `>0x14` unknown-ID logger unchanged. The complete ID-to-target table is generated in ignored `research/cache/custom-vendor/codec-queue-runtime-audit.json`.
- The raw push and event-bit setter each have short, fixed PRIMASK-preserving critical sections and no wait, scheduler call, or retry loop. Static code supports calling those two primitives from the EP0 IRQ, provided the slow wrapper is avoided. This does not prove the overall callback/mailbox integration or that bit 3 immediately wakes a blocked task.
- The reviewed stock command dispatch is sequential. A deferred EQ command placed in this queue could serialize with the stock EQ-open paths in that same consumer, provided it remains in the queue/consumer flow and does not call the setter from EP0.
- An offline executable ring/dispatcher model is provided by `tools/research/codec_queue_model.py`; `PYTHONPATH=tools/research python3 -m unittest -v test_codec_queue_model` runs its tests. This validates the proposed protocol model, not firmware scheduling or DSP behavior.
- Serial processing by the command consumer likely prevents overlap between queued EQ changes and the reviewed stock stream-configuration EQ paths. This does not prove serialization against every codec lifecycle or external caller.

## UNVERIFIED

- The task creation/registration record and priority for `0x20aa20`. The hash-keyed RAM/flash xrefs have no direct caller or literal pointer to `0x20aa20`/Thumb entry `0x20aa21`; raw initialized-RAM pointer scans also find none, so registration may be indirect, built at runtime, or outside these mapped images.
- Whether `0x209a8c` blocks, yields, or merely services pending software/hardware events; the event-set operation itself does not call a scheduler or RTOS wake API. Preemption behavior after event-bit set is therefore not proven.
- Whether any runtime path calls codec EQ/configuration outside the reviewed command loop.
- Whether the app task can safely absorb the hardened ACK wait without delaying other control or audio work at its actual priority. The setter's bounded poll runs in task context without a confirmed yield; interrupts may still preempt, but lower-priority tasks may be delayed.
- Timer callback registrations and the complete task-creation table. Timer-related strings exist, but the existing indexes do not identify a codec-update timer/DPC.

## DISPROVEN

- `af_thread` as a safe synchronous EQ worker: the cached loop is frame-critical and explicitly detects handler overruns/lost signals.
- `usb_audio_enqueue_cmd` as a ready-made EP0 API: on push failure it enters a diagnostic queue-dump/status loop. Use only the bounded raw push plus bounded event-bit setter, with an explicit queue-full response.
- An interrupt/EP0 callback as a safe setter context: the setter performs coefficient generation and hardware ACK polling synchronously.

## Decision

The command loop and ring form a concrete deferred-work candidate and reveal
where Samsung already performs EQ reconfiguration. EP0 can use the raw push
and event-bit setter without waiting or a long interrupt-masked region; these
helpers are bounded and preserve PRIMASK. Event bit 3 is shared state, however,
and no RTOS wake call has been proven. Command ID `0x13` is the only in-table
unknown slot and is a low-collision extension point. A setter hook remains
unsafe to approve because task registration/priority, preemption during ACK
polling, global codec serialization, and runtime mailbox ownership are
unresolved.
